# LLD — Resource store (RT)

> Workstream: [RT](../../definitions.md#rt-dispatcher-runtime) · Task: RT-S1-T01 · Package: `internal/store` (+ `store/memory`, `store/filestore`, `store/objectstore`, `store/journal`, `store/storeaudit`, `store/storetest`)

## Interface

```go
type Object = v1alpha1.Object // GetTypeMeta().Kind, GetName(); metadata through accessors (below)
type Key struct { Kind, Name string }

type Store interface {
    Get(ctx context.Context, k Key, out Object) error                                  // ErrNotFound
    List(ctx context.Context, kind string, opts ListOptions, out any) (ListMeta, error) // out: *[]T, *[]*T or *[]Object
    Create(ctx context.Context, obj Object) error                                       // ErrAlreadyExists; sets ResourceVersion, CreatedAt
    Update(ctx context.Context, obj Object) error                                       // CAS on ResourceVersion → ErrConflict
    Delete(ctx context.Context, k Key) error                                            // ErrNotFound
    Watch(ctx context.Context, kind string, opts WatchOptions) (Watcher, error)
    Lock(ctx context.Context, name string, ttl time.Duration) (Unlock, error)           // advisory, lease-based; waits until free or ctx ends
}

type ListOptions struct { LabelSelector *v1alpha1.LabelSelector; Field map[string]string; Cursor string; Limit int }
type ListMeta struct { NextCursor string; ResourceVersion string } // NextCursor empty on the last page
type WatchOptions struct { LabelSelector *v1alpha1.LabelSelector; SinceVersion string; Buffer int }
type Watcher interface {
    Events() <-chan WatchEvent   // closed when the watch ends (ctx done, Stop, or expiry)
    Err() error                  // after Events() is closed: nil, context error, or ErrWatchExpired
    Stop()
}
type WatchEvent struct { Type WatchEventType /* added|modified|deleted */; Object Object; Version string }
type Unlock interface {
    Unlock()                                            // idempotent; never releases a lock someone else reclaimed
    Renew(ctx context.Context, ttl time.Duration) error // ErrLockLost once expired or released
}

type Sweeper interface { Sweep(ctx context.Context) (SweepResult, error) }
type TranscriptStore interface {
    PutTranscript(ctx context.Context, run string, blob []byte) error // ErrTooLarge over 20 MB
    GetTranscript(ctx context.Context, run string) ([]byte, error)   // ErrNotFound
}
```

Errors (`errors.Is`; most come as `*store.Error{Op, Key, Detail, Err}`): `ErrNotFound`, `ErrAlreadyExists`, `ErrConflict`, `ErrInvalid`, `ErrWatchExpired`, `ErrLockLost`, `ErrTooLarge`, and `ErrReadOnly` (a shared store that stopped writing, §Object store). Optional: `Syncer{Sync(ctx) error}` and `SyncIfSupported(ctx, s)`, for a store shared with other processes (§Object store); `SchemaVersion` and `ReadableSchema` (`schema.go`; `cmd/factory`'s `TestStoredSchema` keeps a golden of every stored kind's JSON fields, compared as a set, pinned to `ReadableSchema`). A change to a stored type needs `ReadableSchema` at `SchemaVersion`+1; once it is pending, further changes accumulate into it (the golden is rewritten at the same version) until a release that reads it ships. Then N+1 is frozen: a later change waits for `SchemaVersion` N+1 to ship and opens N+2 (P3 §Two releases on one log; a test can't know what shipped, so the release checklist does). Bumping both versions at once skips the expand step, and `TestStoredSchema` refuses it. Accessors: `ResourceVersion`, `SetResourceVersion`, `CreatedAt`, `SetCreatedAt`, `HasResourceVersion`, `Labels`; internal kinds outside v1alpha1 implement `MetaObject{GetObjectMeta() *v1alpha1.ObjectMeta}`. Label selectors use `v1alpha1.LabelSelector.Matches`/`Validate`, shared with the catalog.

Kinds stored: `Delivery` (raw provider webhook, pre-normalisation), `Event`, `WorkItem`, `Task`, `Run`, `Agent`, `Effect`, `BudgetCounter`, `Lease` (internal), `Debounce` (internal), `Session` (UI, internal). Config kinds live in the `Catalog` snapshot, **not** in the store.

## In-memory implementation

- One `map[kind]map[name]stored` guarded by a single `sync.RWMutex` (PoC scale: thousands of objects).
- `ResourceVersion` = global monotonic counter (`uint64`, decimal string).
- Objects are **deep-copied** on write and read (JSON round-trip helper; generated `DeepCopy` later if needed).
- **Field indexes** (maintained on write): `Task` by `status.phase`, `spec.queue`, `metadata.workItem`; `Run` by `task`; `WorkItem` by every `links[].provider+ref`; `Effect` by `idempotencyKey`.
- **Watch:** fan-out to subscriber channels with a bounded buffer (default 256). Sends never block the writer: if a subscriber's buffer is full, the store sets its `Err()` to `ErrWatchExpired` and **closes its channel**. Closing always succeeds, so expiry is always observable. Consumers loop until the channel closes, then check `Err()`; on `ErrWatchExpired` the controller runtime re-lists (resync) and starts a new watch. `SinceVersion` replays from a ring buffer of the last 10 000 events; if it's too old, `Watch` returns `ErrWatchExpired` immediately.
- **Locks:** `map[name]{owner, expires}`; `Unlock` is idempotent; expired locks are reclaimable.

## Retention

A sweeper goroutine (every 10 min) deletes:

| Kind | Retention | Rule |
|---|---|---|
| `Run`, transcripts (blob map), `Event`, `Effect` | **90 days** (Q13, configurable `--retention`) | by `CreatedAt` |
| `Task` | 90 days after terminal phase | `Succeeded/Failed/Cancelled` only |
| `WorkItem` | never deleted while any link is open; 90 days after last activity otherwise | |

Transcripts are stored as compressed blobs in a separate `map[runID][]byte`, capped at 20 MB each and 2 GB total (oldest evicted first, logged).

## File store

`store/filestore` is the single-node durable store (design: proposal P2, "The dispatcher keeps its state in a file"). It wraps `store/memory`, which stays the engine: CAS, indexes, watches, locks and retention all come from it, so the file store passes `storetest` unmodified. `filestore.Open(dir, opts, ...Option)` returns a `*Store` (`Store`, `Sweeper`, `TranscriptStore`, plus `Close`, and `Loaded`: what Open loaded, for the caller's start-up log).

```
<dir>/                        0700, owned by the dispatcher's user
  snapshot.json               {"format":1,"storeVersion":"N","objects":[{kind,name,v,created,at,obj}…]}
  journal.jsonl               {"v","at","op","kind","name","obj"?} per change above the snapshot
  transcripts/<run>.jsonl.gz  one file per run (a run name that isn't a safe file name: ~<base64url>.jsonl.gz)
  LOCK                        exclusive flock while open
```

- **Write path:** memory's commit hook (`memory.WithCommitHook`) is called under its write lock once a write is checked and encoded, before it is applied. The file store appends the journal line there and fsyncs it; only then does memory apply the change and tell watchers. A failed append or fsync fails the call and memory is left untouched (nothing to roll back, no watch event to retract), so memory never holds a change the journal doesn't. A failed write is rolled back by truncating the journal to the last good line; a failed fsync (or a rollback that fails) stops all writes (`ErrJournal`) until the store is reopened, since the page cache can't be trusted after it. One fsync per write; group commit would replace the fsync in `append`, not built.
- **Kinds:** loading needs each kind's Go type. The v1alpha1 runtime kinds are built in; internal kinds are registered with `filestore.WithKind(kind, proto)`. A write of an unregistered kind is `ErrInvalid`, so nothing reaches the disk that can't be loaded back.
- **Locks** are not journaled (advisory, lease-based; a restart frees them). **Watches** after a reopen start at the restored version: the history isn't persisted, so an older `SinceVersion` is `ErrWatchExpired`, as when the ring is trimmed.
- **Compaction:** when a write takes the journal past 64 MB or 50 000 lines (`WithCompaction`), on that writer's goroutine (writers that find one running don't wait), and on `Close`. The snapshot is memory at version V (`memory.Snapshot`, one read lock); writes go on meanwhile. Steps: write `snapshot.json.tmp` and fsync; rename over `snapshot.json` and fsync the dir; under the journal lock, write the lines above V to `journal.jsonl.tmp`, fsync, rename over the journal, fsync the dir. A crash after any step leaves the old snapshot and the full journal, or the new snapshot and a journal whose lines at or below V are skipped. A failed compaction is logged and retried after more lines; the write that triggered it has succeeded.
- **Load:** remove leftover tmp files; read the snapshot (an unknown `format` fails Open saying to move the dir aside); replay the journal lines above its version, each exactly one above the last (a gap is corruption); restore memory (`memory.Restore`) and the version counter. A torn last line (no trailing newline, or not a valid line) is dropped with a warning and the journal truncated to the last good line; any other bad line fails Open with `ErrCorrupt` and its line number. Creation times of kinds without metadata (Event) come from the line that created the object.
- **Modes:** dir 0700, files 0600, owned by this user. Open refuses (`ErrInsecure`, naming the `chmod`) a dir or file group or others can access, or a symlink. A second Open of a dir that is open fails with `ErrLocked`.
- **Transcripts** are files with the memory store's caps (20 MB each, 2 GB total, oldest evicted first). Each is written to a tmp file, fsync'd and renamed; its mtime is its creation time on the store's clock, so retention and eviction order survive a restart. Deleted with their Run (from the commit hook) and swept by age.

### Serving (`factory serve --state-dir`)

- **Opening.** `factory serve --state-dir DIR` opens the file store on DIR before anything else and uses it as the `Store`, the `Sweeper` and the server's `TranscriptStore` (transcripts are files). Without the flag the store is in memory, as before; `--dev-fake-providers` and the tests keep memory unless they pass it. The run kit passes `--state-dir "${FACTORY_STATE_DIR:-$HOME/.factory/state}"` (P2 decision 1). An Open error (`ErrInsecure` with the `chmod`, `ErrLocked`, `ErrFormat` saying to move the dir aside, `ErrCorrupt` with the file and line) fails `serve` at start with that message. The start-up log (Info, `store: loaded the state dir`) names the dir, the restored version, the objects per kind, the transcripts, whether there was a snapshot, the journal lines replayed and whether a torn line was dropped (`filestore.(*Store).Loaded`).
- **Kinds.** `serve` registers every internal kind with `WithKind` from one table (`internalKinds`, `cmd/factory/serve_store.go`): `Session`, `Lease`, `AgentToken`, `Enrollment`, `AgentRefresh`, `Delivery`, `EventStatus`, `Debounce`, `TaskPrompt`, `KillSwitch`, and the object store's `StoreLock` and `TranscriptBlob`. `TestServeStoreKinds` parses `internal/` for every type with `GetObjectMeta` (the `store.MetaObject` accessor) and fails when one isn't in the table, or the table names one that no longer is, so a new kind fails a test rather than the first write of a dispatcher with a state dir.
- **Closing.** On shutdown the store is closed last, once the listeners have drained and the controllers, scheduler and sweeper have stopped: `Close` is the final compaction (the journal folded into the snapshot). It runs within `--shutdown-timeout`; if it outlasts it, `serve` returns without waiting, and the next start replays the journal, which holds every change already.
- **Restart.** Everything stored comes back as it was; the components start as on a fresh start and resync from the store:
  - **Work items.** The rebuild from markers still runs, and leaves the work items the file holds alone (`ErrAlreadyExists` → `Existing`): **the file is authoritative for the work items it holds**, and markers only bring back items it doesn't (a dir moved aside, an item created while the state was lost). This deviates from P2's "markers win for projected keys": the projections are written from the stored items, so they only differ when GitHub was edited by hand or the projection lagged, and the stored item also carries what markers don't (decisions, rule state history). The work-item resync still observes each link and emits `factory.workitem.resynced` for changes made on GitHub while the dispatcher was down.
  - **Events.** `EventStatus` is stored, so the rule controller, which lists every Event at start, skips the ones it processed: a restart dispatches nothing again.
  - **Leases and agents.** Leases load as they were. The scheduler's expiry handles one past its TTL as lost (the agent stopped heartbeating), as without a restart. An agent's token is stored as a hash, so an agent that keeps heartbeating across the restart continues: its run completes and its Result and transcript stay readable.
  - **Watches.** Informers start from `List` and watch from the restored version (the history isn't persisted).
  - **Deliveries.** Deliveries stored but not yet normalised are normalised after the restart. `Recover` still runs with `since` = process start; widening it to the restart gap is not built.
- **Tests.** `TestServeStateDirRestart` (register, lease, heartbeat; restart on the same dir; heartbeat, transcript, complete → `Succeeded`, the Result and transcript readable; the rebuild finds the item `Existing` and keeps the stored state over a changed marker; the webhook's decisions and tasks unchanged after two restarts), `TestServeStateDirOpenErrors` (each Open error fails `serve`), `TestServeStoreKinds`.

### Reading the state (`factory state`)

`filestore.Read(dir, opts, ...Option)` loads a state dir **read-only** into a `*View`: a memory store in the reading process (`Get`, `List`), `Loaded` (as Open's), `Journal` (the lines above the snapshot, in version order), `Transcripts` and `Transcript(run)` (the gzip'd file, read on demand) and `Warnings`. It writes, locks and removes nothing, so it works while `serve` has the dir open and on a copied dir (P2 said a shared flock; it takes none, since the dispatcher's exclusive flock would refuse it, and a reader must never block or fail a dispatcher's start).

- **A journal being appended to.** The journal is read once, up to its last complete line: a last line without its trailing newline (an append in flight, or a crash mid-append) is left out, with a warning, and the file is not truncated. Lines are replayed exactly as Open does (a gap or bad line before the last is `ErrCorrupt`).
- **A compaction meanwhile.** The snapshot is opened and kept open while the journal is read; then `snapshot.json` is checked to be still that file (`os.SameFile`; holding it open stops its inode being reused). If a compaction renamed a new snapshot over it, the journal read may already be the truncated one, so Read starts over (at most 10 times in a row, then an error saying to try again). A compaction that renamed before the snapshot was opened is harmless: the journal is the old one, whose lines at or below the snapshot are skipped, or the new one.
- **Modes.** A dir that isn't private (a copy, `cp -r` or `os.CopyFS`) reads with a warning: only a store that writes refuses it. A file that vanishes between the listing and its check (a tmp file renamed by the writer) is skipped, for Open too.
- **`filestore.MoveAside(dir, dst)`** renames the dir for `factory state reset`, holding the dir's flock while it does: `ErrLocked` while a store has it open, and no store opens it midway.

`cmd/factory/state*.go` is the CLI on it: `tasks`, `task`, `run [--transcript]`, `workitem`, `events`, `log` and `reset --yes`, with `--state-dir` (default `$FACTORY_STATE_DIR`, else `~/.factory/state`, as for run.sh) and `--json` (the stored objects, as a `[]` for lists, `{task, runs, decision}` and `{workItem, tasks}` for the two compound views, the journal's own line shape for `log`). Tables drop control characters from cells (agent and provider text may hold terminal escapes) and cut them at 60 characters; multi-line fields keep their newlines. The task's "dispatched by" is the newest fired decision on its work item with the task's provenance (event, RuleSet, rule). `log`'s notes follow each Task's phase and each Run's end through the journal; an object's first line in it has no earlier state to compare with (that is in the snapshot). An unknown id is "not found" with the ids sharing the longest prefix with it. No state dir is a message naming `--state-dir`, `FACTORY_STATE_DIR` and run.sh's default. Tests: goldens of every subcommand on a fixture dir that a test builds through `filestore.Open` (snapshot part and journal part, a failed implement run with its Result, transcript and progress, a work item with decisions, events processed and not), read while the store is open and checked unchanged byte for byte; `--json` decoded back and compared with the store; a copy with a torn last line; reset refused while open, then moving the dir; in the package, Read against Open's state, torn lines at every offset of the last line (bytes unchanged), reads concurrent with writes and compactions, a compaction forced between the two reads (and ten in a row).

**What never reaches the disk.** The stored kinds carry no credential, and two tests keep it so: one fails when a kind reaches the disk without an audit line (`storeaudit.KindAudit`, shared with the object store), one scans every byte of the snapshot and journal of the conformance run and of a fixture with a real-shaped object of every kind (strings, and base64 `[]byte` fields decoded) for `ghs_`, `gho_`, `ghp_`, `github_pat_`, `sk-ant-`, `-----BEGIN` and `x-access-token:`. The audit:

| Kind | Why it holds no secret |
|---|---|
| Event, WorkItem, Run, Effect, BudgetCounter, Approval, KillSwitch, EventStatus, Debounce | provider refs, rule state, results and counters; no credentials |
| Task | `spec.credentials` describes the git token to mint; tokens are minted per lease and never stored; `llm` is always `agent-local` |
| Agent, AgentToken | the agent token is stored as a `sha256:` hash only |
| Enrollment, AgentRefresh | the enrollment and refresh tokens as `sha256:` hashes only, with the pool, owner and host name an admin fixed |
| StoreLock | a lock's name, the holding store's instance id, a random per-hold id and an expiry |
| TranscriptBlob | a transcript blob's run name, random id, size and put time (the blob itself is agent output) |
| Lease | the lease and usage; git credentials never stored, only their expiry |
| Session | named by the hash of the session id; holds the login, no GitHub token |
| Delivery | the raw webhook minus `Authorization`, `Cookie`, `Proxy-Authorization`; untrusted, not secret; body and headers dropped once handled |
| TaskPrompt | the rendered prompt: catalog templates and untrusted provider text |

## Object store

`store/objectstore` is the store several dispatchers share (design: proposal P3, "The dispatcher keeps its state in object storage", and ADR-0009). Like the file store it wraps `store/memory`, which stays the engine in every dispatcher: CAS, indexes, watches and retention come from it, so it passes `storetest` unmodified, over the fake bucket and the `file://` bucket. The bucket holds the authoritative history: an append-only log of create-only objects, one per change, plus snapshots. `objectstore.Open(ctx, bucket, opts, ...Option)` returns a `*Store`: `Store`, `Sweeper`, `TranscriptStore`, `store.Syncer`, `Close`, plus `Loaded` (what Open loaded, for the start-up log), `Ready` (for `/readyz`) and `Compact`.

```
<prefix>/
  log/00000000000000001043.json           {"v","at","op","kind","name","obj"?,"w":{"id","nonce"},"schema"}: one change
  snapshots/00000000000000001000.json.gz  {"format":1,"storeVersion":"N","schema":S,"objects":[…]}, gzip'd
  transcripts/<run>.<id>.jsonl.gz         one blob per put of a transcript or environment log
```

The log entry is P2's journal line plus `w` (the writer's instance id and a per-write nonce) and `schema` (the writer's `store.SchemaVersion`); the snapshot is P2's plus `schema`. Both formats live in `store/journal`, which the file store uses too, with no change to its files (it leaves `w` and `schema` out). Names are zero-padded to 20 digits, so a listing comes back in version order.

- **Write path.** Memory's commit hook (now given the write's `ctx`) creates `log/<v>` if absent, under memory's write lock, with a 5 s deadline per request:
  - *Created:* committed; memory applies it and tells the watchers.
  - *Taken:* the entry is read back. Its own nonce (an SDK retry whose first attempt landed) is committed as if created, so `update()`'s callers never apply a change twice. Another nonce is a lost race (`errBehind`): memory is untouched, the store syncs and runs the caller's operation again on the fresh state (`ErrAlreadyExists`, `ErrConflict`, `ErrNotFound`, or the next free version). After 20 lost races in a row the write fails with `ErrContended`.
  - *Unknown outcome* (a timeout or 5xx): read back as for "taken", with a context of its own, so a write whose caller gave up still learns whether it landed. Missing: the create is tried once more. When the create and the read-back both fail, the write fails saying its outcome is unknown, memory is untouched, and if the entry did land the next sync applies it.
  - *Refused writes are checked too.* A write memory refuses without reaching the log (`ErrNotFound`, `ErrAlreadyExists`, `ErrConflict`) syncs once and runs again, unless a sync started since the write began. So a delete of an object another dispatcher created a second ago finds it, and every write is checked against the log's tail.
  - A Run's delete (Sweep's too) is noted by the hook in the write's context; once the write is done, the Run's transcript and environment log go, record and blob.
- **Reads and freshness.** `Get` and `List` answer from memory. They sync first when the last sync is older than the sync interval (`WithSyncInterval`, default 2 s; a failure is logged at warn and the read is served from memory). A `Get` that finds nothing syncs once more before answering `ErrNotFound`, and returns the sync's error rather than a `ErrNotFound` it can't vouch for. A sync reads `log/<rv+1>`, `log/<rv+2>`… until one is missing (one GET of a missing object when the store is current) and applies them with `memory.Apply`, which fires their watch events in version order. Syncs are serialised and shared: a caller needs a sync that *started* after it asked, so concurrent callers ride one. `Sync(ctx)` (`store.Syncer`) forces one, and `store.SyncIfSupported(ctx, s)` is what a caller acting on an empty lookup uses (memory and the file store have nothing to sync). A background loop syncs every interval, on the store's clock, so watches stay live; correctness never depends on it.
- **Lag.** A store whose last successful sync *started* more than `MaxLag` ago (`WithMaxLag`, default 1 h) reloads before it writes or reads: it lists the log after its version, and when the listing doesn't start at `rv+1` (entries were deleted), or is empty while a newer snapshot exists, it starts again from the newest snapshot (`memory.Replace`, which expires every watcher with `ErrWatchExpired`, so informers re-list). A write never goes out while that reload fails. `MaxLag` must be under the segment retention; Open refuses otherwise.
- **Versions.** `store.SchemaVersion` (written) and `store.ReadableSchema` (the newest read without losing data, at most `SchemaVersion`+1) ship expand-then-write (`internal/store/schema.go`). An entry past `ReadableSchema` stops the store writing: every write, Lock and transcript put fails with `ErrReadOnly` (serve maps it to 503), `Sync` returns it, reads go on from what the store has, and `Ready` says why. Open loads the log up to such an entry and starts read-only. A snapshot past `ReadableSchema` refuses Open with `ErrSchema`, naming both versions. A snapshot is labelled with the newest schema among the entries it holds, not only its writer's. `cmd/factory`'s `TestStoredSchema` holds the JSON field paths and kinds of every stored type (`testdata/store/schema.golden`, the v1alpha1 runtime kinds plus `internalKinds`) and the `ReadableSchema` they belong to: compared as a set. A change needs a pending `ReadableSchema` (`SchemaVersion`+1): without one it fails, saying how to ship it, and `-update` refuses; while one is pending, further changes accumulate into it until a release that reads it ships; then it is frozen until `SchemaVersion` catches up. Bumping both at once is refused.
- **Ready.** `Ready()` is nil once the load (the first sync) has succeeded, while the store writes, and while its last successful sync started within `MaxLag`; after `Close` it is `ErrClosed`.
- **Locks.** A lock is a `StoreLock{holder, token, expiresAt}` record named after the lock, written through the log. Lock creates it, or takes over an expired one with a CAS update; while another holder has it, Lock waits for a local Unlock, a sync that changes a lock record, the store's clock reaching the expiry (so storetest's fake clock drives it) or its 1 s sync tick, until `ctx` ends. Renew is a CAS update (`ErrLockLost` once expired, released or taken over). Unlock deletes the record only at the version this holder last wrote (`memory.DeleteAt`), under its own 5 s deadline; a failure is logged at warn and the record expires. The sweeper deletes expired records the same way (counted under `StoreLock` in `SweepResult.Objects`).
- **Transcripts.** Each put creates a new blob, `transcripts/<run>.<id>.jsonl.gz` (P2's escaping for an unsafe run name, `<id>` 16 random hex digits), with create-if-absent, then writes the run's `TranscriptBlob{id, size, putAt}` record through the log (`putAt` on the store's clock) and deletes the blob the record named before. A read follows the record to its blob, and once more, after a sync, if a re-put replaced it in between (a read-only store answers from what it has). A drop deletes the record at the version it read, then only the blob that record named; a record that changed (a re-put) or is gone is left alone, and an eviction moves on to the next oldest. So a drop and a re-put on two dispatchers can't remove each other's blob, in either order. The caps and eviction read the records from memory: the oldest `putAt` goes first, then the lower resourceVersion. Retention sweeps the records by `putAt`. The sweep's maintenance (below) lists `transcripts/` and deletes blobs whose id no record names once they are over a day old (a crash between the blob and its record, or a replaced blob whose delete failed). The bucket needs no unconditional put.
- **Compaction, cold start and retention.** The sweep (the leader's, PR 5) compacts when the log is 1 000 entries past the newest snapshot it knows of (`WithCompactEvery`), and `Close` and `Compact` compact too: `snapshots/<V>.json.gz`, create-only, so a second compaction at one version is a no-op. Open lists `snapshots/`, reads the newest, lists `log/` after it and reads those entries 16 at a time, checks they are contiguous from V+1 and restores memory; a snapshot or entry deleted meanwhile makes it start again (5 times at most), and so does an empty tail while a newer snapshot has appeared (its entries were deleted after `snapshots/` was listed). The sweep's maintenance, at its first run in a process and then once a day, deletes the log entries the newest snapshot covers that are older than `SegmentRetention` (7 days; the listing stops at the first newer one) and the snapshots that are neither the newest two nor younger than it, by the bucket's object times against the store's clock. There are no bucket lifecycle rules.
- **Buckets.** `Bucket{Get, Create (if absent), List (name order, after startAfter), Delete}` with `ErrNotExist` and `ErrExists`: every object is created once and never overwritten. `NewFakeBucket(clock)` (tests: call counts, planted objects, and a fault hook that fails a call, reports it timed out after it landed, answers `ErrExists` after a create landed, or races it by writing through another store first). `NewFileBucket(dir)` (`file:///abs/dir`): 0700, writes go to `.tmp/`, are fsync'd, then linked into place, and the dir is fsync'd. `ParseURL(ctx, rawURL)` opens `file://`, `gs://`, `s3://` and any scheme registered with `RegisterScheme` (tests); an unknown scheme names the known ones. `ctx` bounds the opening (finding credentials), not the bucket's requests. A URL may carry a credential, so its errors never repeat it: a URL that doesn't parse gets only the cause, with what it quotes masked, and others the URL with its whole userinfo masked (`objectstore.RedactURL`: `url.URL.Redacted` masks only a password, and the user alone may be the secret); `file://` refuses userinfo. The `gs://`, `s3://` and `FACTORY_S3_ENDPOINT` errors print nothing of the value but its scheme, and say which part is wrong: a secret with '/', '?', '#' or '"' lands outside the userinfo (`s3://KEY:/secret@bucket/p` puts it in the path), so no masking of one part keeps it out.
- **Cloud buckets.** `gs://bucket[/prefix]` and `s3://bucket[/prefix]`: a bucket of `a-z0-9-_.` and a prefix of segments of `A-Za-z0-9-_.`; a user, an '@' anywhere, a port or ':', a query, a fragment or an escaped prefix is refused, since credentials only come from the platform's identity, never from the URL, a flag or the config. Each request's deadline is its context's, which the store sets (5 s).
  - `GCSBucket` (`cloud.google.com/go/storage`), with Application Default Credentials. Every call uses the JSON API, reads too, so one set of errors applies. `Create` is one multipart upload with `ifGenerationMatch=0` (412 → `ErrExists`); the chunk size holds the whole object, so the SDK buffers it and retries it on a 408, 429, 5xx or a broken connection (with chunk size 0 it would stream it and never retry). `Get` and `Delete` map a missing object's 404 (`ErrObjectNotExist`) to `ErrNotExist`, keeping the SDK's error in the chain. A missing bucket is not `ErrNotExist`: the SDK reports it as `ErrObjectNotExist` too, so its 404 is told apart by the JSON error's message ("The specified bucket does not exist."; the reason and domain are the same as an object's), and as `ErrNotExist` a vanished bucket would read as a current log and serve stale state. `ParseURL` also lists one object under the prefix at open, so a missing bucket fails the start. The client is made with `context.WithoutCancel` of the open's `ctx`: some ADC sources (`authorized_user`, `external_account`) keep that context for every token refresh. `List` uses `startOffset` (inclusive, so `startAfter` itself is skipped). `STORAGE_EMULATOR_HOST` (the SDK's own variable) points it at an emulator, without credentials.
  - `S3Bucket` (`github.com/aws/aws-sdk-go-v2/service/s3`), with the SDK's default chain (Lambda's role; a region is required: `AWS_REGION`). `Create` is `PutObject` with `If-None-Match: *` (412 → `ErrExists`); the SDK retries 5xx and timeouts. A 409 `ConditionalRequestConflict` (another conditional write to the key in flight) is sent again up to 3 times, 100 ms apart and doubling, and is an unknown outcome when it persists. `Get` maps `NoSuchKey` (not `NoSuchBucket`) to `ErrNotExist`. `List` is `ListObjectsV2` with `StartAfter`. `Delete` is `HeadObject` (404 → `ErrNotExist`), then `DeleteObject`, which succeeds whether or not the key exists. **`FACTORY_S3_ENDPOINT`** (`https://host[:port]`, or `http://` only on a loopback host: `localhost`, `127.0.0.1`, `[::1]`) points it at an S3-compatible server such as MinIO, with path-style addressing; anything else, credentials (an '@') included, is refused with an error that prints none of the value. Credentials and region still come from the default chain.
  - Either way an SDK retry of a create whose first attempt landed answers `ErrExists`, which the write path's nonce check commits as the write's own.
- **A `file://` bucket and a P2 state dir never share a directory.** `NewFileBucket` refuses a dir holding `snapshot.json`, `journal.jsonl` or `LOCK`; `filestore.Open` and `filestore.Read` refuse one holding `log/` or `snapshots/` (`filestore.ErrObjectStoreDir`).
- **Kinds.** `StoreLock` and `TranscriptBlob` are registered by every object store, and are in `internalKinds` (so the file store registers them too, and never writes them). Other internal kinds come with `WithKind`, as for the file store.
- **Secrets.** `store/storeaudit` holds the kind audit (§File store's table), the token scan and a real-shaped fixture of every kind. The file store's tests and the object store's run them: every kind in the log entries and snapshots of the conformance run and of the fixture has an audit line, and no token marker is anywhere in them. `TestInternalKindsAudited` keeps `internalKinds` and the audit's table equal.
- **Tests.** `storetest.Run` over the fake and `file://` buckets; two stores on one bucket (CAS with one winner, creates with one winner, watch order, lock exclusion and reclaim, a link found through `Sync`, writes checked against the tail, a newer schema stopping the other store with nothing lost, a rollback within `ReadableSchema` keeping the newer fields, a newer snapshot refusing Open); faults (a lost race at every kind of write, 20 lost races, creates that timed out and landed or didn't, an SDK retry that landed charging a BudgetCounter once, a failed Unlock, GET and LIST errors during sync, a writer paused past `MaxLag` and past the segment retention that never re-creates a deleted entry); cold start from every combination of snapshot and tail, with deletes and with covered entries deleted, and with a compaction and retention mid-load; transcripts across stores, eviction order and orphans; the buckets (one conformance table, `testBucket`, for every bucket), the guards, `ParseURL`, the `gs://` and `s3://` URLs, and the GCS and S3 error mapping against canned HTTP servers; the secrets audit.
- **Emulator tests** (opt-in, Docker: `make e2e-objectstore`; CI's advisory `e2e-objectstore` job). `TestEmulators` runs, on `gs://` against `fake-gcs-server` and on `s3://` against MinIO (`pgsty/minio`, the community build: `minio/minio`'s images are no longer published): the bucket conformance through `ParseURL`; eight conditional creates of one name at once (one winner, the others `ErrExists`); a create that landed and whose response is replaced by a 503 (the SDK retries it and gets `ErrExists`; through the store, an update committed once at one version, read from a second store); and `storetest.Run` through the object store. Both emulators honour the preconditions (`ifGenerationMatch=0`, `If-None-Match: *`). Garage (`dxflrs/garage` v2.5.0, and its main branch on 2026-10-27) was tried in MinIO's place and doesn't: a `PutObject` with `If-None-Match: *` on a taken key answers 200 and overwrites it, so a race of creates has several winners.

**Not checked here.** A real cloud bucket is only exercised by a deployment: the emulators stand in for GCS's and S3's conditional creates, listing order and times, S3's 409 `ConditionalRequestConflict` (MinIO doesn't send it; the canned-server test does), Application Default Credentials and the default chain on Cloud Run and Lambda, and the buckets' policies.

### Decisions taken in the object store (P3 PR 1)

- **`file://` creates link an fsync'd tmp file into place** (`link(2)` fails when the name is taken), rather than P3's `O_CREAT|O_EXCL` then fsync: the precondition is the same, but a concurrent reader never sees a half-written entry, and a crash never leaves a torn entry that, being create-only, could never be rewritten.
- **The commit hook takes the write's `ctx`** (`memory.CommitHook`), so the PUT honours the caller's cancellation; the file store ignores it.
- **An unknown outcome is retried once** (two creates at most), because the hook holds memory's write lock: a bucket outage then stalls reads for about 20 s per write, not indefinitely.
- **A write memory refuses syncs once** (above), which P3's "writes are always checked against the latest state" needs and its write path alone doesn't give.
- **A `Get` that can't sync returns the sync's error**, not `ErrNotFound`; one that finds the store read-only answers from memory.
- **The orphan scan uses the blob's age** (no record names its id, and it is older than a day) rather than tracking "no record for a day" in memory, so it holds across restarts and leaders.
- **Each transcript put gets its own blob** (P3 §Transcripts, after review): with one name per run, a re-put landing between a drop's record delete and its blob delete lost its blob while its record stayed. Unique names make drops and re-puts independent, and `Bucket.Put` went from the interface.
- **Compaction runs from `Sweep`, `Close` and `Compact`.** Snapshots are create-only and named by version, so any instance compacting is safe; with one dispatcher it is the leader.
- **Retention and the orphan scan run from `Sweep`, at its first run in a process and then once a day**: an instance that scales to zero may never live a day, and the cost is a few LISTs per leader start, since listing the log stops at the first entry too new to delete.
- **`ErrClosed`, `ErrContended`, `ErrSchema` and `ErrCorrupt`** are the package's errors; `ErrReadOnly` is the store's, for serve to map.
- **The schema golden compares field paths and JSON kinds**, not Go type names, so renaming a Go type isn't a schema change but renaming a field or changing its kind is.

### Decisions taken in the cloud buckets (P3 PR 2)

- **The buckets live in `objectstore`**, registered in `ParseURL`'s table, rather than in packages that register themselves when imported: `serve` gets them by importing the store, and the binary carries both SDKs (`factory`, linux/amd64, from 35.9 MB to 80.6 MB, 25.1 MB to 56.2 MB stripped, measured in PR 2: most of it is the GCS SDK's gRPC and OpenTelemetry dependencies; `factory-agent` is unchanged).
- **`ParseURL` and `Opener` take a `ctx`**: opening a cloud bucket finds credentials and reads the SDK's config, which is I/O.
- **GCS reads use the JSON API** (`storage.WithJSONReads`), not the SDK's default XML API, so every call has the same errors, and fake-gcs-server serves them on any host.
- **GCS uploads set a chunk size that holds the object**, so the SDK can retry them; chunk size 0 is never retried.
- **S3's 409 `ConditionalRequestConflict` is not `ErrExists`.** It means another conditional write to the key is still in flight, so the object may not be readable yet; as `ErrExists` the write path would read nothing back and report `ErrCorrupt`. It is sent again a few times, then is an unknown outcome, which the write path reads back and retries.
- **S3's `Delete` checks with `HeadObject` first**, since `DeleteObject` succeeds on a missing key and the `Bucket` contract answers `ErrNotExist`. A missing bucket looks the same to a HEAD; every caller ignores `ErrNotExist` on a delete.
- **`FACTORY_S3_ENDPOINT` turns on path-style addressing** with the endpoint: S3-compatible servers expect it, and AWS itself never needs the variable. **It must be `https://`** except on a loopback host (Gustavo, 2026-10-27): requests carry SigV4 signatures and the state, and only a local emulator goes without TLS.
- **GCS tells a missing bucket from a missing object by the error's message**, since storage v1.70.0 maps both 404s to `ErrObjectNotExist` and GCS gives both the same reason and domain; a list at open makes a missing bucket fail the start as well.

## Postgres later

`store/storetest` holds a **conformance suite** (`func Run(t *testing.T, newStore func(store.Options) storetest.Subject)`) covering CAS conflicts, watch ordering, resync, selectors, locks and retention. A future Postgres store must pass the same suite. The file store (§File store) is the single-node durable store and the object store (§Object store) the shared one, which both pass it; Postgres stays an option for a heavier write load.

## Tests

- Conformance suite on `memory` under `-race`.
- Concurrency: 50 goroutines updating the same object → exactly one wins per version.
- Watch slow-consumer → channel closed, `Err() == ErrWatchExpired`, then successful resync; writer never blocks.

## Decisions taken in RT-S1-T01

- **`store.Object = v1alpha1.Object`**, not a store-specific interface: v1alpha1 kinds carry no `GetResourceVersion`/`SetResourceVersion`, so the store reaches metadata through accessors (a type switch over the runtime kinds, plus `MetaObject` for internal kinds).
- **Event** has no metadata: the store keeps its version and creation time beside the object, and `Update` on an Event is unconditional (no CAS). Every other kind's `Update` requires the stored `resourceVersion`; an empty one is `ErrConflict`.
- **`List` returns `ListMeta{NextCursor, ResourceVersion}`**: the cursor for pagination (keyset, name order, opaque), and the store version at list time, so a consumer can list then `Watch(SinceVersion: meta.ResourceVersion)` with no gap (resync).
- **`Unlock` is an interface with `Renew`.** A lease that has expired is lost: `Renew` returns `ErrLockLost` even if nobody reclaimed it, and the old holder's `Unlock` is a no-op.
- **Retention and transcripts are separate interfaces** (`Sweeper`, `TranscriptStore`), not part of `Store`; `store.RunSweeper(ctx, s, interval, log)` is the ticker helper (default 10 min).
- **Suite signature:** `storetest.Run(t, func(store.Options) storetest.Subject)`, with `Subject = Store + Sweeper + TranscriptStore`. The suite injects a fake clock and small caps, buffers and history sizes through `Options`.
- **Retention specifics:** Event by the store's creation time; Task by its last write in a terminal phase (`Succeeded/Failed/Cancelled`; there is no terminal timestamp); `BudgetCounter` swept at 90 days with Runs, Events and Effects; Agent, Approval and the internal kinds kept; a Run's transcript is deleted with the Run (and transcripts also age out on their own). WorkItems are never swept by the store: the work-item controller owns their retention (it knows whether links are open).
- **`--retention`** is wired by `factory serve` into `store.Options.Retention`; the store only takes the option.
- **Clock:** the store takes an `internal/clock.Clock` (`Real`, `Fake`). `rules.Clock` has the same shape and should converge on it.

## Decisions taken in the file store (P2 PR 1)

- **Journal before apply, under memory's write lock** (the commit hook), not apply-then-roll-back: a rollback can't retract a watch event already sent, and readers would see a change that may vanish. The cost is that reads wait for a write's fsync; group commit is the seam if that matters.
- **The hook is the only change to memory:** `WithCommitHook`, `Snapshot` and `Restore`. Without a hook memory behaves as before (`New` takes the options variadically). (P3 later gave the hook the write's `ctx`, and added `Version`, `Apply`, `DeleteAt` and `Replace` for a shared log; the journal line and snapshot encoding moved to `store/journal`, unchanged on disk.)
- **Snapshot objects carry `v`, `created` and `at` beside `obj`**, as journal lines carry `v` and `at`: Event has no metadata, and SinceUpdated retention needs the last-write time.
- **Kinds are registered** (`WithKind`) rather than learned at write time, and an unregistered kind can't be written: a kind that could be stored but not loaded would fail the next start.
- **A failed fsync stops writes until reopen** (`ErrJournal`); a failed write that was rolled back doesn't.
- **Transcript names:** safe run names are the file name; others are `~` + base64url, so no run name can escape `transcripts/`.
